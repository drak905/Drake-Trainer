# Safety Review — Trainer Application (adversarial, UX-only)

Verdict: FAIL — do not proceed to build; first-run-only UNSAFE gate, FR-13 refusal UX, and SM-C1 unprompted-write paths are unsafe as specified.

Scope: `DESIGN.md` + `EXPERIENCE.md` (spines win) + `reconcile-prd.md` gap 4. App writes to game memory via CE: one-shot parameterized writes, freeze repeated-writes, nop/replace code patch. Safety invariants assumed: UNSAFE first-run-only gate, persistent armed banner, offline-only + multiplayer/anti-cheat refusal, restore-on-exit, SM-C1 zero unprompted writes, BSOD-prevention CE setting.

## Findings

- F1 [critical] — First-run-only checkbox insufficient for repeated freeze/patch sessions. Location: `DESIGN.md` Components gate-checkbox (L59-61, L112-114); `EXPERIENCE.md` Component Patterns UNSAFE checkbox (L65), State Freeze armed/off (L94), Flow UJ-3 (L143-148). One checkbox in Setup modal, "never asked again," permanently arms both Freeze (repeated writes) and Patch (code modification, strictly higher risk) with no per-session, per-process, per-action, or per-target re-consent, no revocation/disarm UI, persistence mechanism explicitly `[ASSUMPTION]`. Consent decays; user armed weeks ago forgets. Buried far from destructive controls (proximity violation). Fix: split Freeze vs Patch gates; require per-session re-arm + just-in-time confirm at Freeze ON / Patch writer adjacent to the button; add explicit Disarm control; persist armed state per-launch only, not forever.
- F2 [critical] — FR-13 refusal UX unspecified; user can drift into banned target before any block. Location: `reconcile-prd.md` gap 4 (L20, L28); `EXPERIENCE.md` State Refuse (L100), Banned everywhere (L111). No block point (attach vs scan vs write), no refusal copy, no heuristic-vs-attestation presentation; "refuse via `showerror`" is dismissible via Esc and does not specify detach, PID lockout, or disabling of Adjust/Freeze/Patch after dismiss. Read-side flow (attach→capture→extract→CE expanded scan) can fully proceed against a multiplayer/anti-cheat process before refusal fires; CE scan itself touches the target. Fix: pre-attach gate at Process surface (blocklist + heuristic warning + offline-only attestation) that on hit detaches, locks that PID, disables all write paths, and requires explicit target change; specify exact refusal copy; answer open Q #4.
- F3 [critical] — SM-C1 bypass via keyboard slip, live-selection drift, and UJ-2 silent re-apply. Location: `EXPERIENCE.md` Interaction Primitives Enter/Tab (L106-109), Freeze/Display + Patch rows (L74-75), Key Flows UJ-2 (L136-141), Banned everywhere (L111). (a) `Enter` activates focused button — focused Freeze ON / Patch writer fires a repeated-write/code-patch with no second confirm. (b) Freeze binds to listbox selection; unspecified whether changing selection while frozen retargets writes to a new address. (c) UJ-2 "values land without repeating capture/extract/scan" specifies no plan-preview or confirm before re-apply writes — a file-open becoming a memory write. Each violates zero-unprompted-writes. Fix: destructive buttons excluded from Enter-default + require blocking confirm per (address, label, old→new); freeze binds to snapshotted (address+label) not live selection; UJ-2 re-apply requires per-cheat plan + confirm, never auto-write on profile open.
- F4 [high] — Destructive-write preview is display-only, not consent; one-shot write may fire without affirmative approval. Location: `EXPERIENCE.md` Adjust row (L28), Multiplier input (L71), State Model-unreachable (L91), Primitives "preceded by plan or confirm" (L109); `reconcile-prd.md` gaps 1-2 (L24-26). Plan placement, default/prefill, bounds, and error copy all unspecified; fallback (`Adjust model unreachable — local ×100 fallback.`) is a disabled-log line the user may never see, silently changing write semantics from model-computed to ×100. "Shown before write" ≠ confirmed before write. Fix: blocking Write-preview dialog (address, label, extracted×multiplier, fallback disclosure, BSOD-setting status) with explicit Write/Cancel; validate multiplier bounds (reject ≤0/non-numeric/huge-overflow) with error copy; make fallback a Use-fallback/Abort choice, never log-only.
- F5 [high] — Restore-on-exit covers only normal quit; crash/kill path leaves freeze/patch resident. Location: `EXPERIENCE.md` Freeze armed/off "restore on quit" (L94), Patch "restore on exit" (L95, L75), Flow UJ-3 climax (L145-147). No crash/kill handling (app kill via Task Manager, app exception, power loss, game crash first, CE disconnect), no restore-failure copy, no next-launch stale-patch/freeze detection, no dirty-flag in RUNBOOK/profile. If CE owns the freeze timer/NOP, killing the UI may not stop it. User quits believing safe. Fix: quit-time restore checklist dialog with per-item restored/failed status; on-launch stale-state detector + recovery banner; document kill-path as known limitation in armed banner copy; prefer fail-safe CE mechanisms.
- F6 [high] — Armed banner persistence/unmissability unverifiable and likely below fold. Location: `DESIGN.md` unsafe-armed-state (L50-54, L75, L112); `EXPERIENCE.md` Armed-warning banner (L66), Accessibility Floor (L118). Placement given only as "Body/Extras" in a 900×700 all-visible grid — Extras is where attention is not during Adjust/Verify; no sticky-header/above-grid requirement, no occlusion/minimize/modal-dialog behavior, and banner text content (unlike every other string) has no exact copy, so AA/text+icon claims cannot be verified. Mode combobox itself has "no badge in as-built," so the Adjust section shows no armed signal. Fix: fix banner to sticky header row above body grid with exact copy (e.g. `UNSAFE ARMED — Freeze/Patch can corrupt saves; restore on quit; offline games only`), mirror compact armed chip adjacent to Freeze ON and Patch writer, never dismissible while armed.
- F7 [medium] — Patch confirm and helper copy invite risky action without risk disclosure; narrow/error lines misreadable as permission. Location: `EXPERIENCE.md` Voice and Tone (L42, L54), Component Patch writer (L75). `Change the value in-game now so the watch can catch the writer… Continue?` frames debugger-attach + timed in-game mutation as benign, omitting crash/BSOD/ban/save-corruption risk. `{exc} Change the value in-game, then use Verify…` instructs mutating game state to aid the scanner and can be read as clearance to proceed; `Drafts written… Verify each in-game before promoting` does not say offline-only. Verify `Correct?` biases Yes-to-persist under refine-loop pressure. Fix: append risk suffix to Patch confirm (`This attaches a debugger and patches code. It can crash or corrupt saves. Offline saves only. Continue?`); reword narrow line as instruction-not-permission with offline-only reminder; make fallback/narrow states require explicit user choice.
- F8 [medium] — Editable-value + multiplier gaps allow writing an unintended value. Location: `reconcile-prd.md` gaps 1-2; `EXPERIENCE.md` Editable value field (L70), Multiplier input (L71), Flow UJ-1 steps 4-5 (L130-133). "Edit via field" with no commit/cancel/validation and no stale-vs-edited indicator; multiplier with no default, bounds, or preview placement — overflow/zero/negative writes possible, and Verify compares against the wrong expected value. Fix: explicit commit model (field + Apply/discard, edited-dirty marker on value row), numeric validation before plan, plan echoes the exact committed operands.
- F9 [low] — BSOD-prevention CE setting has no UX gate. Location: implicit across scan/write rows (L72-75); dropped-trust-tone note in `reconcile-prd.md` (L34). Nothing requires verifying the CE anti-BSOD setting before first scan/write, and Setup Test only checks `/models` reachability. Fix: Setup checklist item + pre-write guard that blocks scan/write until the CE safety setting is confirmed, with exact copy and failure path.
- F10 [low] — Refusal/trap copy lives outside the spine, so safety copy is unreviewable. Location: `EXPERIENCE.md` L56 (`exact trap wording lives in PRD/FR-4 detail`), L100. Six manual-trap strings and FR-13 refusal strings are incorporated by reference only. Fix: inline exact `showerror` strings into the spine or normatively link PRD section/line numbers; no assumed copy for refusal paths.

## Strongest good-faith defense of the current design (3 bullets max)

- Single-window, selection-gated, exact-string discipline with plan-before-write, Verify Yes-only-persist, unique-signature-only patch, and a global refuse-and-stop rule is a coherent minimal-consent skeleton that directly encodes SM-C1 intent.
- First-run gate plus always-text+icon persistent amber banner correctly keeps the common one-shot flow uncluttered while reserving friction for the genuinely repeated/destructive modes (freeze/patch).
- Restore-on-quit plus no-hotkey/no-overlay/no-auto-rescan bans show deliberate blast-radius restraint: no background writers, no blocking CE thread, no silent re-targeting by design.
