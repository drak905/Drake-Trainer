# Accessibility Review — Trainer_Application (WCAG 2.2 AA)

Verdict: NOT YET AA — fix the 3 high findings (contrast pairings, screen-reader exposure, error identification) before build; mediums before freeze/patch ships.

Scope: `DESIGN.md` + `EXPERIENCE.md` (ux-Trainer_Application-2026-10-02), solo Windows CustomTkinter 6.0.0 single 900x700 window, wizard setup/attach/capture/extract/adjust/verify/freeze/patch/drafts. User decision honored: warnings text+icon, never color-only.

## Findings

- [high] Color-contrast pairings undefined — DESIGN.md Colors + Components/button-primary, unsafe-armed-state: hexes alone do not pass/fail; `foreground: system-native` is not a testable pair. `#0078D4` with white text is ~4.0–4.2:1 (fails 4.5:1 for 12px body/button text; passes 3:1 UI-component only) and `#4CC2FF` with white text fails on dark. Amber/red deltas look correctly chosen (`#B45309` light / `#FBBF24` dark; `#D13438` / `#F1707B`) but only if paired explicitly. Fix: lock pairs per theme (e.g. light button: white on `#0078D4` only if bold/large or darken to pass 4.5:1; dark button: near-black on `#4CC2FF`; amber/red used for text only on stated surfaces), measure with a contrast tool in light + dark, record ratios in DESIGN.md.
- [high] Screen-reader exposure is assumed, not specified — EXPERIENCE.md Accessibility Floor + L120 (`announces window title, section label, listbox row, status/log on change [ASSUMPTION]`): Tk/CustomTkinter has weak UIA/MSAA exposure and a `disabled` log widget is skipped by tab order and most SRs, so status/log changes and `label: value [type] conf=0.XX` rows have no guaranteed name/role/live-region. Fix: assign accessible names to every entry/combobox/button/listbox, expose status line + log as polite live region (do not use a disabled widget for live text), verify row readout order, test with Narrator + NVDA in both themes.
- [high] Error identification has no field association — EXPERIENCE.md State Patterns (`showerror Attach/Capture/Extract/Scan/Verify/Runbook/Patch failed`, Setup `Failed: {exc}`): dialog alone does not say which field failed or how to recover (WCAG 3.3.1/3.3.3). Fix: prefix each dialog with the field label (e.g. `Process — Attach failed: <reason>`), mirror the message inline next to the failing entry, and on dismiss move focus to that field; keep `showerror` icon+text, never red-color-only.
- [medium] Modal keyboard contract incomplete — EXPERIENCE.md Interaction Primitives + Component Patterns/Setup modal (`Enter/Escape [ASSUMPTION]`, `Esc closes topmost`): no focus trap while Setup/`askyesno` is open, no focus return to invoker (Settings button), no defined default/safe focused button. Fix: trap Tab inside modal, return focus to invoker on close, make Verify `Value now shows {observed} (expected {expected}). Correct?` default to `No`, ensure Yes/No are Tab+Arrow+Enter operable without pointer.
- [medium] HiDPI/text-scaling reflow unproven — DESIGN.md Layout & Spacing (fixed 900x700 min, fixed listbox h6/h8/h5, all-sections-visible, `HiDPI correct via CustomTkinter; no custom DPI handling`) + 10px caption: at 125/150/200% Windows scaling the grid will clip with no scroll/wrap plan. Fix: allow window resize beyond minimum with a scrollable body grid, let listboxes/rows scale with system text size, test 125/150/200% for no loss or overlap (1.4.4/1.4.10), do not fix caption at 10px physical.
- [medium] Focus-visible + forced-colors not verified — EXPERIENCE.md Accessibility Floor (`focus visible via CustomTkinter defaults`): defaults are untested in light/dark and Windows High Contrast, and 2.4.11/1.4.11 need a ≥3:1 indicator. Fix: define an explicit focus ring (outline, never color-only change), verify in light/dark/HC forced-colors mode, never remove the outline.
- [medium] Drafts/Mode state encoding fragile — EXPERIENCE.md Drafts (`[verified]/[UNVERIFIED]` prefixes) + Mode combobox (`text-only, no badge`): brackets/case-only distinction breaks if color is later added and all-caps brackets read poorly in SRs. Fix: keep words not styling as the signal (e.g. `Verified: x` / `Unverified: x` with distinct icon+text), keep amber/red out of drafts/mode, preserve the persistent UNSAFE text+icon banner as the sole amber use.
- [low] Pointer target size unspecified — dense body grid + listbox rows, no 2.5.8 (24×24 CSS px min) treatment. Fix: ensure all buttons/checkbox/combobox rows meet 24×24 min with adequate spacing; do not shrink hit areas to fit 900x700.

## What is fine as-is

- Text+icon warning discipline (amber UNSAFE banner, never color-only; destructive confined to error dialogs) directly satisfies 1.4.1 — hold this line.
- No time-limited interaction assumed (non-blocking CE scan, non-blocking Verify Yes/No, no timeouts) — 2.2.1 needs no fix.
- Single-window reading-order Tab plan with no hotkey/overlay/trap surfaces is the right floor — keep header→Process→Capture→Extract→Adjust→Verify→Extras order and Esc-closes-topmost rule.
