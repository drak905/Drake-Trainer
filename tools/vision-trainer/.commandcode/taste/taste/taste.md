# Taste
- Prefers simple solutions and minimal overhead over elaborate options — e.g. trimmed a two-class/lambda test fake down to a single context-manager fake. Confidence: 0.85
- Prefers auto-approve / autonomous workflow without intermediate confirmation prompts. Confidence: 0.9
- Extracts a shared helper when two call sites need identical fallback/error handling (capture and verify share `_grab_game_rect`) instead of duplicating try/except blocks. Confidence: 0.8
- Parses external/bridge data defensively: per-row tolerance for malformed entries and explicit RuntimeError for impossible states (e.g. no monitors available). Confidence: 0.75
- When review reveals a missed case, generalizes the fix to the whole case family and adds sibling guards/tests rather than patching only the flagged instance. Confidence: 0.75
- Degraded-path log/error messages name the triggering reason (e.g. "Window rect unavailable ({exc}) — falling back…"), and exact user-facing copy is pinned by test assertions. Confidence: 0.75
- Headless-safe tests: wrap Tk app construction in try/except tk.TclError and pytest.skip("no display available"). Confidence: 0.7
- Runs the full offline test gate (pytest vision_trainer/tests -q -m "not live") after every patch round and again before committing. Confidence: 0.85
- After implementing a story, dispatches a blind review subagent that must return at least a size-derived floor of findings (N = min(floor(sqrt(kB)+1), 10)) as a plain markdown list that looks "for what's missing, not only what's wrong"; patches findings and logs the rest as Patched/Deferred accounting in the story spec. When a follow-up pass is needed, it runs the same floor protocol but is explicitly scoped to not re-report findings already patched since the first pass. The reviewer prompt is tightly contained: no skills, no sub-subagents, findings returned as plain text rather than routed through any findings-reporting tool. Confidence: 0.8
- Keeps per-story artifacts in lockstep with code (spec Implementation Notes, story status flips, sprint-status.yaml), commits with a conventional-scoped message once the gate is green, and ends the turn by announcing the next story. Confidence: 0.75
- Numeric edits validate at the commit boundary against the item's declared value type — integer types (byte/word/dword/qword) must parse as int, floats reject inf/nan — rather than a generic parse, with the number-vs-integer wording of the error copy tracked to type. Confidence: 0.7
- Tk widgets that share a window with an Entry which can take text selection get exportselection=False (e.g. the values Listbox) so selecting text in one control can't clear the other's selection. Confidence: 0.7
- Full-suite-only test flakes are reproduced before touching product code: subset bisection, pytest -rs for skip reasons, and a throwaway repro script (e.g. under _bmad-output/, always deleted before commit); if still unreproducible, record it as a known flake in the story spec instead of shipping a speculative fix. Confidence: 0.7
- Patch passes keep tests and helpers lint-clean: strip f-prefixes from placeholder-free f-strings, fix test-name typos immediately, and remove vestigial params / dead placeholder methods once flagged by review. Confidence: 0.7
- Never-write-unseen gate for irreversible external actions: CE memory writes must pass a blocking preview dialog with a safe default No (Enter and Escape both cancel; approval only via explicit button click — "display-only is not consent"), and the flow API enforces the gate by making the writer callback required (missing writer → error) so a write is unreachable without previewed consent; a cancel routes back to the refine stage. Confidence: 0.8
- LLM-driven plans degrade to deterministic local fallbacks when the model is unreachable, and the degraded path is disclosed in the UI (plan-fallback line in the preview dialog) and stamped into durable outputs (write_result / runbook fields like multiplier and fallback_used) for later audit. Confidence: 0.7
- Prefers one-time persistent setup automation for repeated environment steps (e.g. CE autorun auto-loading bridge script) over manual per-launch actions. Confidence: 0.7
